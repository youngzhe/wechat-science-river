# 小墨团 3D IP 叠加设计规格

## 目标

将现有小墨团正面插画发展成可复用的立体角色雏形，并叠加到微信小程序的主要角色展示位。保留当前原生小程序与轻量 2.5D 视觉路线，让小墨团成为后续章节可继续扩展的 IP。

## 已确认方向

- 使用项目内 `miniprogram/assets/xiaomotuan-small.png` 作为造型参考。
- 风格延续现有可爱、手绘质感：煤灰色圆润身体、琥珀金色大眼、额顶火苗、蓝绿色围巾。
- 通过 `img2threejs` 创建程序化 Three.js 角色模型，按技能要求逐阶段建模并检查多角度；单张正面图无法提供背面事实，侧面和背面按同一 IP 语言做明确的风格化补全。
- 角色在离线环境中渲染为透明背景的多角度素材，运行时仍使用原生小程序图片组件和现有 CSS 动画，不在小程序里增加 Three.js/WebGL 渲染器。
- 首页、书房对话和结案页继续支持当前 2D PNG 回退图。角色素材必须可替换、可迭代，不把 3D 几何烘焙成唯一资产。

## 用户体验

- 首页：继续展示完整小墨团，保持现有轻微悬浮待机动作。
- 书房对话：使用更紧凑的角色立绘；透明素材边缘应清楚，不遮挡对话文本。
- 结案页：继续作为收尾陪伴角色展示。
- 立体感通过不同朝向/表情的预渲染帧与柔和投影体现。首版不提供自由 360 度旋转、骨骼驱动或复杂表情动画；如果角色框可轻触，可切换到一个侧向/回望帧并在短暂延时后回到正面。
- 可视区域、帧率或加载异常时安全回退到原有 `xiaomotuan-small.png`。

## 素材与工程边界

- 建模源代码和可重复渲染步骤作为 IP 源资产保留在 `wechat-science-river/` 内。
- 小程序只打包所需透明帧；不打包建模工具链、Three.js 或 GLB。
- 素材应控制尺寸和帧数，避免角色图片显著增加小程序首包；优先评估一张正面 hero 图 + 少量角度帧，而不是高帧率 sprite sheet。
- 帧文件需有稳定命名，并在角色组件中集中管理映射；页面不能各自维护一份路径。

## 验收标准

1. 正面可辨认并保留既有 IP 的主要轮廓、火苗、眼睛和围巾配色。
2. 正面、侧面、背面检查图中的体积与遮挡关系自洽；背面推测部分在文档中标为风格化设计。
3. 至少提供适合首页与紧凑对话位的透明渲染素材；边缘无背景色晕、裁切、地面穿插或阴影硬边。
4. 首页、书房和结案页用同一个角色素材映射/组件，2D 原图仍可回退。
5. 新增角色素材大小经过记录；新素材和页面操作不影响小程序既有核心模型与存档测试。
6. 在可用的微信开发者工具中检查透明边缘、尺寸、安全区与页面往返；若当前环境无开发者工具，只能报告静态与自动化检查结果，不宣称完成真机验收。

## 不在本轮范围

- 对书房背景做 3D 重建。
- 实时 Three.js 小程序运行时、可旋转 3D 查看器、骨骼绑定、语音口型、全套表情系统。
- 发布级品牌规范、商标注册或儿童市场合规评审。

## 主要风险

- 单张正面图不足以确定背面造型；首版模型会有合理但非参考图可验证的补全。
- `img2threejs` 规定的阶段门槛可能发现模型质量不适合直接进入最终素材；此时应迭代模型或保留现有 2D 方案，不跳过质量门。
- 预渲染角度少时旋转互动会是离散切帧，不能表现连续视差；首版应以精致定帧和轻动效为主。
